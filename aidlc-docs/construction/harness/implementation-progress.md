## 4. 运行与验收

以下命令从项目根目录开始。首次环境可在 server 虚拟环境安装 `requirements-test.txt`。

### 离线测试（不调用模型）

```sh
cd server
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m app.harness.evaluators.regression
.venv/bin/python -m app.harness.evaluators.tool_probe --kind knowledge
.venv/bin/python -m app.harness.evaluators.tool_probe --kind fact
```

独立前端验证：

```sh
cd frontend
npm test -- --runInBand --silent
npm run build:full
```

### 真实模型质量评测（会产生调用费用）

```sh
cd server
.venv/bin/python -m app.harness.evaluators.regression --live --case role-injection
.venv/bin/python -m app.harness.evaluators.regression --live
```

默认用例经过新 Runtime，通常调用 NPC、评分、独立目标判断各一次，工具往返最多额外两次 NPC 调用，失败可能重试。明确角色接管样例改由应用策略回复并保留原评分/目标，零模型调用，不计入模型抗攻击成绩。加 `--legacy` 可对照旧链路。输出包含合成测试对话的真实回复、评分、Trace、逐调用用量和人工评审标准；不是用户真实会话。简单关键词检查只筛查明显回归，不能替代人工判断或证明安全性。

新 Runtime 的 `early-fact` 检查最早预算是否进入三条模型输入；已通过离线测试，但不证明真实模型一定正确使用事实。`--legacy` 对照仍保留固定窗口的已知缺口。

### 启用内嵌 Worker（默认方式）

```sh
cd server
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

默认 `JOB_WORKER_ENABLED=1`。首次启动只增量建表，不清空旧数据；已结束会话的旧 pending/processing 报告会加入队列并开始真实模型调用。升级前应先备份数据库，确认模型凭证与预算。

### 单独 Worker

API 进程设 `JOB_WORKER_ENABLED=0`，在相同 server 目录、相同数据库与模型环境下另开进程：

```sh
.venv/bin/python -m app.workers.jobs
```

关闭内嵌 Worker 后必须确实运行独立 Worker，否则任务只会排队。单进程 Worker 串行消费，多个 Worker 可原子领取；此版本只适合同机 SQLite，不推荐跨主机共享 SQLite 文件。

默认：轮询 1 秒、租约 30 秒、每次尝试最长 900 秒、最多 3 次 Job 尝试。租约到期的恢复由运行中的 Worker 执行，因此“可恢复”不等于服务停机时仍会继续计算。

Provider 请求无法由线程强制取消；超时后旧计算结果无法回写，但可能仍产生 Provider 费用。后台任务是至少一次执行、幂等提交，不是模型恰好调用一次。后续可升级为可终止子进程或外部任务队列。

### 生产配置与观测

- `APP_ENV=production`，随机长 `JWT_SECRET`，`AUTH_DEV_BYPASS=0`。
- `CORS_ORIGINS` 必须填写真实前端 HTTPS origin，不能用 `*`、路径、查询或尾部 `/`；HTTPS 需由部署网关提供。
- 配置有效模型凭证、对话及复盘模型；校验不联网验证余额/模型可用性。
- 响应头 `X-Trace-ID` 可关联 `.trajectories/events-YYYY-MM-DD.jsonl` 的请求、模型和任务事件。
- 新元数据文件默认保留 14 天，清理在有新事件时触发；磁盘不可写时观测会降级并记录警告，不应把“请求正常”当作“轨迹必然写盘”。
- 旧版本原文轨迹未被自动读取或删除，需负责人按隐私策略另行审查；本次没有删除用户历史文件。
- Compose `/health` 检查是存活检查，不证明模型、数据库写入及 Worker 队列全部健康。
