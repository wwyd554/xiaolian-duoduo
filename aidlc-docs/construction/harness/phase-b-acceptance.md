# 阶段 B：权威状态与上下文第一版验收

日期：2026-09-05。依据：`docs/销练多多-Agent-Harness改进方案.md`。

## 交付范围

本次实现统一 Runtime 的第一版，不是完整 Agent Harness，也不是自由规划、多工具自主执行 Agent。开发结果尚未部署或重启至用户正在使用的服务。

1. 会话创建时固定场景、客户和目标快照，服务端维护 PracticeState；客户端提交的身份、情绪、目标状态不再作为权威输入。
2. NPC、评分、独立目标判断共享有预算的上下文，保留最近对话和有来源的早期信息。
3. 评分与目标判断分离。目标改变需附消息证据，自动结束由后端决定。
4. 每轮消息、状态修订、完成标记及复盘入队同事务提交，防止并发重复轮次和失败半写入。
5. 前端允许撤销误判目标，不再凭本地目标状态自动结束；请求失败保留用户输入，不伪造 NPC 回复。结束接口失败不跳转，完成快照在服务端确认后缓存，卸载时清理跳转计时器。
6. 补齐创建会话的场景可见性、会话 ID 归属和自定义场景非所有者编辑权限。

## 状态与数据

新增 SQLite `session_states` 表，按会话保存 JSON 状态与递增 revision。事实、摘要、目标证据暂存于该 JSON 内，尚未拆分独立查询表。

状态包含场景快照、轮次、阶段、情绪指标、目标状态、带来源事实、摘要、结束原因及上下文统计。结束原因分为用户手动结束、必要目标完成、轮次上限、历史已结束。

`GET /sessions/{session_id}/practice-state` 仅供会话本人读取；响应不返回 userId 或整个场景快照。复盘也读取固定快照，源场景后来编辑或删除不会改变新会话的复盘口径。

历史会话在首次加载/保存时兼容迁移。没有旧快照时只能使用当时仍可读取的场景，无法恢复过去已被编辑或删除的原始版本；旧目标标记为未验证，不能直接当作自动完成证据。新旧 Runtime 切换后按已持久化消息重新对齐轮次。

## 记忆与预算约束

- 记忆是关键词分类的原文摘录，不是模型自由编写事实。分类包括需求、预算、异议、决策人、承诺。
- 每条保留来源消息、用户/客户角色和不确定性；用户说法不等于客户确认，模拟客户说法也不等于真实世界核实。
- 跳过问句、超过 400 字的单句，每条消息最多抽取 8 条。可能漏掉没有关键词或复杂跨句表达，不能宣称完整语义理解。
- 修改预算时保留新旧来源，不自动把旧说法改写为新事实；模型须结合时间顺序与条件判断。
- 超预算时移除较早的完整历史，生成有界原文摘要，再缩短摘要/舍弃部分记忆，同时记录遗漏数量。不会悄悄截断系统约束、必要场景目标或当前消息；必要内容仍过大则明确拒绝。
- 第一版使用 UTF-8 字节数作为保守输入预算估计，并预留生成回复及消息包装空间。它不是供应商精确 tokenizer，不等于实际计费 Token；轨迹区分 estimated_input_tokens 和实际使用量。
- 预算内优先保留同类型/角色的最新与最早摘录，但不保证无限历史全量召回；摘要截断会显式标记。

## 独立目标判断

评分只负责指标、解释和提示，不接受其 goalUpdates。独立判断器必须返回完整、无重复的既定目标集合，严格布尔值和有效置信度。

改变目标需满足置信度至少 0.85、引用真实同会话消息、证据为包含否定和条件的完整原句。达成还要求用户与 NPC 双方证据，虚拟开场白不能充当客户达成确认。验证失败保留旧状态，不自动结束；评分失败保留旧指标并提示不可用；NPC 失败不写入半轮对话。

只有场景明确设置 `isRequired: true`，必要目标全部满足证据规则，且独立判断器明确返回 completed，才按目标完成自动结束。没有必要目标时不猜测完成标准，仍可手动结束或到轮次上限。目标判断可撤销以前误判的达成。

`verified` 表示通过判断器与机械证据检查，不代表第三方核实或语义必然正确。完整句校验与双角色门槛比较保守，可能使真实已完成目标暂时未被识别，需要真实模型测量误报/漏报。

## 配置与回退

```dotenv
HARNESS_RUNTIME_ENABLED=1
CONTEXT_INPUT_BUDGET=16000
MAX_MESSAGE_CHARS=4000
```

以上为默认值；需重启后端生效。未修改用户实际 `.env`。预算允许 8000–64000，单次消息上限允许 1–8000 字符。

`HARNESS_RUNTIME_ENABLED=0` 回到旧双调用对话链路，但仍保留服务端场景快照、权限校验与状态同步，不恢复客户端覆盖权威场景的行为。已有数据库只增量建表；上线前应备份。

通常每轮 NPC 与评分并行两次，再串行一次目标判断；没有目标则跳过第三次。相较旧链路可能增加费用与延迟，尚无真实供应商成本/延迟基线。Worker 升级启动可能补做已有待处理报告，启动前需检查模型预算，详见总开发记录。
