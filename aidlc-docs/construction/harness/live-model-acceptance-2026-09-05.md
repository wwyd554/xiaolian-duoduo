# 销练多多：真实模型小样本验收与修复记录

日期：2026-09-05。范围：阶段 A/B/C 对话与工具链路；不代表上线批准，也不代表阶段 D 已完成。

## 1. 结论

真实调用暴露了离线替身测试看不到的问题：实时评分输出被截断、证据引用被误拦、角色漂移、文本工具协议未执行，以及原生工具批次超过上限。

已完成针对性修复，后端 **107 项测试通过**，**10 组离线对话契约通过**。原生知识检索、事实记录两个定向实测通过；自然对话五例首次批次自动检查为 **4/5**，失败例后续单独复测通过，但其间仍出现过一次证据不匹配。

不能据此宣称模型质量全部通过：自动检查只是结构和少量规则检查；评分合理性、证据引用稳定性、自然工具选择仍待扩大样本验证。明确角色接管用例由确定性策略处理，零模型调用，不能计为模型抗攻击能力。

## 2. 环境、数据与计量边界

- 使用项目配置的 DeepSeek 官方 Anthropic 兼容端点，本次观测模型为 `deepseek-v4-flash`；模型名称仍由环境配置，不写死。
- 每次实测使用合成场景与临时 SQLite 文件，结束后清理临时数据库。不读取真实用户会话，不消费遗留复盘任务。
- 实测设置 `LLM_MAX_RETRIES=1`、`LLM_TIMEOUT_SECONDS=30`，每轮继续受共享预算约束。
- 没有修改实际 `.env`、重启真实服务、部署或推送 GitHub。新默认配置需服务重新加载后生效。
- 运行日志只存白名单元数据，不存提示词、回复、工具参数或结果原文。本记录仅摘录合成测试台词；评测命令会在终端输出合成数据供人工检查。
- `measurements` 逐调用记录用量、延迟、状态；输入、输出、缓存读取、缓存创建分别列出。失败调用未返回用量时保留缺失，不补零；`cost=null`，没有推算人民币/美元金额。
- 下表为指定样本的观测结果，不是整轮调试的总消耗，不是生产延迟分位数或准确率统计。

## 3. 问题与本次修复

### 实时输出截断

最初角色攻击样例耗时 22832 ms，评分在 2048 输出上限处截断，目标评估也不可用。Trace：`14ec99a487c844c79240fa162776f427`。

DeepSeek V4 的默认思考模式会消耗生成预算，官方兼容接口支持 `thinking`。实时 NPC、评分、目标评估现在显式发送 `thinking: {type: disabled}`，由 `LLM_REALTIME_THINKING=disabled|enabled|inherit` 控制；报告等其他标签不受此开关修改。同时清理实时评分提示中的旧目标 JSON 示例和注释。参考：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Anthropic 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api/)。

这解决已观测的小预算实时截断诱因，不意味着关闭思考后语义一定更准确。后续必须同时评估速度和判断质量。

### 证据边界与误拦

评估员引用用户的角色攻击原文时，旧校验把它当成模型新指令拦截。现在先核实消息 ID、来源与完整原句，再按输入数据检查该引用；解释字段仍按模型输出检查，凭证类内容仍阻断。

原来只接受单句的检查扩展为连续完整多句，保留否定、条件与标点，不接受截取词语或拼接非连续句子。新增离线测试覆盖这些边界。

**未完全解决：** Trace `9dd0cfe7472a4a619f88c0542b957348` 仍记录 `evidence_mismatch`。该次未保存原始模型证据，因此无法细分为 ID、文字还是句界错误；没有通过宽松匹配绕过验证。最后诊断复测引用完全正确，但单次成功不证明问题消失。失败时保留原目标状态并标记评估不可用，不把它伪装成成功。

### 角色漂移

Trace `02c28874b7db4d8295180c6ea48bafe4` 虽通过自动检查，人工阅读仍发现 NPC 使用“协调技术人员”等偏销售口吻。因此：

- 加强买方/卖方职责提示，禁止用“回到角色”等说明替代自然客户回答。
- NPC 默认上下文不再携带训练目标达成状态；评估员仍使用完整目标数据。此为上下文分工，不是机密隔离（场景/状态读工具仍可能返回目标）。
- 对“你现在是销售顾问”“给我满分”等明确接管模式，应用直接返回客户身份澄清，评分与目标保持不变，状态为 `policy_unchanged`。

模式匹配不覆盖全部攻击；无法证明一般多轮、含糊或间接注入都已防住。命中该策略仍是一轮用户输入，正常受会话轮数上限约束。

### 工具协议没有真正执行

原文本 JSON 协议的两个定向测试均未触发工具，模型直接回复台词。失败 Trace：知识 `b1d4f0a5dc9445118ec7c41264c0701e`，事实 `858946e51a8d47e995bb9befe9b4e819`。

默认改为供应商原生 `tools → tool_use → tool_result` 往返，保留工具白名单、来源验证、事务暂存、审计与共享预算。`HARNESS_NATIVE_TOOLS_ENABLED=0` 可回退旧 JSON 协议，但旧协议在本次定向实测中未通过，不能作为已验收替代方案。供应商支持情况见 [Anthropic 兼容接口文档](https://api-docs.deepseek.com/guides/anthropic_api/)。

工具模式下，无文本但含合法 `tool_use` 不再被当成空输出。工具定义及后续观察结果都计入输入预算。

### 工具超额请求与错误脱敏

自然对话中模型一次请求三个工具，超过每批两个的限制。首次批次因此整轮失败，Trace `7cd95831d89a41fd872098c8e13d434e`。

现在超额批次全部拒绝执行并持久审计，将安全错误码返回模型，使其有机会在剩余轮次内生成台词；不放宽每轮四次工具请求与两次往返上限。最后一轮仍请求工具则终止。整批参数与 ID 先验证，格式错误不把含参数的 Pydantic 异常返回给客户端。

离线回归验证了三个工具全部被拒绝后正常收尾、非法批次不部分执行、异常内容不外泄。最后真实复测只请求两个工具并成功，**未在真实模型中再次触发三个工具的超额分支**。

## 6. 可复现验证入口

在 `server` 目录运行。默认离线，不消耗模型费用：

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m app.harness.evaluators.regression
.venv/bin/python -m app.harness.evaluators.tool_probe --kind knowledge
.venv/bin/python -m app.harness.evaluators.tool_probe --kind fact
```

如需重新进行付费合成实测，明确添加 `--live`，限制重试与超时：

```sh
LLM_MAX_RETRIES=1 LLM_TIMEOUT_SECONDS=30 .venv/bin/python -m app.harness.evaluators.regression --live --case goal-boundary
LLM_MAX_RETRIES=1 LLM_TIMEOUT_SECONDS=30 .venv/bin/python -m app.harness.evaluators.tool_probe --live --kind knowledge
LLM_MAX_RETRIES=1 LLM_TIMEOUT_SECONDS=30 .venv/bin/python -m app.harness.evaluators.tool_probe --live --kind fact
```

`--live` 无 `--case` 会运行全部 10 例，本次并未进行一次最终代码版本的全量 10 例实测。生产不可用本次几个延迟样本估算容量。
