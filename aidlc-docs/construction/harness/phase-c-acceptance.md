## 1. 模型可选工具循环

NPC 可以直接回复台词，也可选择工具，收到执行结果后继续生成台词。当前默认使用原生 tools/tool_use/tool_result；旧 JSON 协议保留为可配置回退，但在首次真实模型定向探针中未触发工具，不作为已验收替代方案。无效协议不会作为台词展示或落库。

最多两次工具往返，每次最多两个调用；第三次 NPC 模型调用必须生成最终台词。超出循环预算的调用请求也记录为拒绝。每次模型输入继续受上下文预算限制；工具结果过大则明确拒绝，不截断系统约束或当前消息。

原生超额批次全部拒绝，安全错误观察返回模型，在剩余额度内允许收尾；未增加执行权限或预算。原生工具定义也计入上下文与共享预算。

| 首批工具 | 参数 | 实际能力 |
| --- | --- | --- |
| get_scenario_context | 空对象 | 读取本场固定场景快照 |
| get_session_state | 空对象 | 读取本场状态和最近 20 条事实，标明遗漏数量 |
| retrieve_sales_knowledge | query | 关键词匹配两条内置训练规则，返回本地来源和版本 |
| record_customer_fact | messageId、quote、type | 按完整原句暂存事实，应用事务最终决定是否提交 |

内置知识只涉及需求确认与证据/承诺边界，不包含企业资料、真实产品参数或投资收益数据，不联网、不提供法律/投资建议。企业资料导入、可见性管理、版本索引和语义检索仍在阶段 D；本版不是企业知识库。

## 2. 权限、证据与审计

- 用户身份、会话和角色由应用绑定，模型不能指定 userId、其他 sessionId 或更高权限。
- 注册表是封闭白名单；schema 严格校验类型并禁止额外字段，未注册工具默认拒绝。
- 副作用分只读、业务写入、敏感外部操作；当前没有开放敏感外部操作，没有 SQL、Shell、文件或网络工具。
- NPC 不获得评分、目标更新、结束练习、复盘入队或画像写入工具。这些仍由独立 Evaluator 和应用事务裁决。
- 事实必须匹配当前会话真实消息 ID 与完整原句；问句不作为事实。角色、不确定性由来源推导，模型不能冒充客户确认。类型仍由模型选择，原句匹配不能证明分类或语义一定正确。

新增 `tool_audits` 表。PreToolUse 先独立提交 started；PostToolUse 更新 completed、denied、failed 或 staged。任一审计写入失败，停止该轮业务写入。

审计记录 trace、会话/用户 ID、白名单工具名、副作用、参数字节数、状态、固定原因码和耗时；不记录原始参数、对话、工具结果、凭证或异常堆栈。未知工具名记为 unregistered，避免恶意工具名泄露内容。

写事实先暂存，再将消息、事实、状态修订、自动结束、复盘入队与审计 committed 标记放入同一业务事务。模型失败或事务回滚会留下 staged 审计，但不会保存事实。staged 不等于已提交；崩溃可能留下 started/staged，供故障排查。

审计连接绑定 Runtime 实际数据库文件，合成评测不会回落到用户数据库。按 TRACE_RETENTION_DAYS 保留，在下一次工具调用清理过期记录。审计仍含用户/会话标识，需要内部访问控制。

## 3. 模型预算

新 Runtime 每轮用线程安全的共享预算覆盖 NPC、评分、目标判断与供应商重试；失败尝试也扣额度，不返还。

默认最多 12 次供应商尝试、总预留额度 120000。预留为保守 UTF-8 输入估计、包装余量与输出 Token 上限之和，不是精确 tokenizer 或货币额度。通常无工具为 3 次逻辑调用，两次工具往返时最多 5 次，无目标再少一次；重试另扣尝试额度。

NPC 预算耗尽则整轮不提交；评分/目标预算耗尽则标记 unavailable 并沿用原状态。每次输入仍受 CONTEXT_INPUT_BUDGET 限制，工具观察结果太大可能让本轮失败，需要缩短内容或调整预算。

尚未实现账户每日额度、价格换算、全站模型并发限流、熔断与跨供应商 fallback。预算每请求重新建立，不是全站成本封顶，也不覆盖旧 Runtime 和其他模型接口。

## 4. 内容安全基线

local-sales-v1 对新 Runtime 的输入、历史文本、场景、工具参数/结果、NPC/评分/目标输出实施规则检查：

- 阻断可识别的 API 密钥、私钥标头和配置中的实际长凭证。
- 阻断场景、工具内容中部分明确的系统规则覆盖/泄露指令。
- 用户角色攻击可作为训练输入保留并标记，但不扩大工具权限。
- 拦截部分明显危险销售输出，例如保证稳赚或索取密码/验证码。
- 保留通用错误消息，不向 HTTP 返回供应商原始异常。

这只是确定性模式匹配，有误报/漏报风险，不覆盖全部混淆、多语言和间接注入，也没有覆盖所有报告/场景生成链路。不是全面内容审核服务。护栏列表会说明策略和 Runtime 启用状态，不再声称已经接入云端审核。

## 5. 语音资源保护

- TTS 必须携带有效 JWT；现有前端已发送认证头，成功响应结构不变。文本上限 2000 字符（含 SSML），等待合成最多 30 秒，每用户最多两个并发。
- ASR 必须具有有效 JWT、本人已创建且活跃的会话，检查浏览器 Origin；接收数据期间约每五秒复核会话状态，并检查令牌到期。
- ASR 每用户一个连接；收到数据时检查 15 分钟连接上限，60 秒无数据关闭。
- 单帧 PCM 上限 65536 字节且必须偶数字节，JSON 文本上限 100000 字符，拒绝非法 Base64。持续语音约 20 秒自动分段。
- ASR、TTS 各默认全机四个并发；每用户每服务固定自然分钟 30 次连接/合成请求；ASR 每用户每分钟最多 75 秒等量 PCM。固定窗口边界可能产生双倍短时突发，不是平滑令牌桶。
- SQLite `resource_rates` / `resource_leases` 在共享同一数据库的进程间生效。断开释放租约；TTS/ASR 崩溃租约分别在 60/1800 秒后回收。
- ASR 不再打印识别原文；Uvicorn access/error 日志过滤 WebSocket token 查询参数。代理和第三方日志仍需自行关闭查询参数记录，后续宜改为短期连接票据。

Whisper 仍是阻塞线程推理，无法强杀已运行任务；断开或应用取消不保证 CPU 任务立即停止。高负载生产应迁移隔离进程/独立 ASR 服务，租约不是硬取消保证。应用检查发生在接收消息后，网关仍须限制 HTTP 请求体/WebSocket 帧大小。

## 6. 开关与升级

```dotenv
HARNESS_RUNTIME_ENABLED=1
HARNESS_TOOLS_ENABLED=1
HARNESS_NATIVE_TOOLS_ENABLED=1
LLM_REALTIME_THINKING=disabled
RUNTIME_MODEL_ATTEMPTS=12
RUNTIME_RESERVED_TOKENS=120000
SPEECH_REQUESTS_PER_MINUTE=30
SPEECH_CONCURRENCY=4
```

以上为默认值，`.env.example` 已更新；未修改实际 `.env`、未重启服务。HARNESS_TOOLS_ENABLED=0 仅关闭工具，保留阶段 B 和本次 Runtime 规则/预算；HARNESS_RUNTIME_ENABLED=0 回退旧对话链路，此时新 Runtime 的工具、安全和共享预算不生效，但语音鉴权/限流和场景权限不回退。不删除历史状态或审计。

`HARNESS_NATIVE_TOOLS_ENABLED=0` 回退文本 JSON 协议；`LLM_REALTIME_THINKING` 可设 disabled/enabled/inherit，仅控制实时 NPC、评分和目标评估，不改变报告配置。模型更换时需重新验证工具协议和质量，再启用灰度。启动增量建表，升级前备份数据库；原有 Worker 可能补做待处理付费报告，需先确认预算。
