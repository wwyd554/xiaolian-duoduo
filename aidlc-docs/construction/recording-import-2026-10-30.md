# 录音文件导入与本地转写

日期：2026-10-30。

录音复盘已接通“上传录音 → 本地转文字 → 核对后生成复盘”的完整路径，不再要求用户预先在其他工具中转写录音。

## 两步导入

1. **导入录音**：选择音频文件，在运行项目后端的电脑上调用 faster-whisper 转写。页面展示处理状态，支持取消等待。
2. **核对并复盘**：查看、编辑或拆分识别出的文字，逐条指定“我（销售）”或“客户”，补充标题和沟通背景。用户确认后才保存文字并进入原有复盘队列。

Whisper 返回的是带起止时间的文字片段，不包含可靠的说话人识别。一段录音可能只返回一个较长片段，不能据此假定一段对应一个人；用户需要拆分、核对角色。系统不会自动把相邻片段轮流标成销售与客户。

## 接口与限制

新增鉴权接口 `POST /reviews/transcribe`，请求类型为 `multipart/form-data`：

- `file`：录音文件，支持 MP3、WAV、M4A、AAC、OGG、FLAC、WebM。
- `language`：`zh`、`en`、`ja` 或 `auto`，默认为 `zh`。
- 文件最大 **50 MiB**，录音最长 **15 分钟**。解码时同时检查文件元数据和实际采样数量。
- 转写文字最多 **30000 字**；超过 200 个片段时合并相邻片段并保留完整文字。若超过文字或单段 4000 字限制，明确报错，不静默截断。

返回结构：

```json
{
  "text": "识别出的完整文字",
  "segments": [{ "start": 0, "end": 3.2, "text": "一个文字片段" }],
  "durationSeconds": 10.41,
  "language": "zh"
}
```

此接口只返回转写结果，不创建会话或复盘记录。确认后仍调用 `POST /reviews/import`，使用 `source: "audio"`；现有导入校验要求 2–200 条消息，包含销售和客户双方角色。

## 本地处理与资源生命周期

录音识别复用本地已缓存的 faster-whisper 模型。文件转写显式启用 `local_files_only=True`，不会临时联网下载模型，也不会把录音交给云端语音识别服务；本地模型未就绪时返回可读错误。当前开发环境使用已缓存的 `base` 模型。

“本地”指运行项目后端的机器。转写后确认生成复盘仍使用项目已有的模型分析流程，不能把整个复盘过程描述为完全离线。

原始音频不作为产品数据持久化，不写入 SQLite。上传后仅建立随机命名的临时文件；工作线程成功、失败或响应取消标志退出时，都会删除临时文件并释放语音并发租约。确认的文字则按原有复盘流程存入数据库。

用户取消等待后，正在执行的一次模型推理可能需要到片段边界才能停止。线程退出前继续持有临时文件和并发租约，避免提前删除正在使用的文件或错误开放并发槽位。录音任务每 30 秒续期租约，以覆盖运行较慢的长录音。
