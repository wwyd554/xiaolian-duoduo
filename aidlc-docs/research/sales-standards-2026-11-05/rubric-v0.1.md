# 销练多多通用销售陪练评分标准 v0.1（适配草案）

日期：2026-11-05。状态：研究适配稿；已据此开发 `xiaolian-sales-core / 1.0.0`，实际实现与边界见 [实施记录](../../construction/business-rubric-v1-2026-11-05.md)。尚未完成业务门槛校准。

实施说明：1.0.0 的 S3 评价价值表达与需求的对应关系、已知条件及未知边界，不因系统未接入产品资料就强制封顶 1 分。明确说明待核实、没有编造确定性效果，并得到客户回应，可以达到 2 分；产品事实和承诺授权另外列为待核实。当前风险项只有待核查提示，尚无人工确认/排除工作流。下文人工审核与阈值校准属于后续业务闭环设计，不能理解为已经上线。

本稿参考 LeadMagic 的行为评分量表和异议处理流程、Yz613 的评分与权重分离，以及 zhixun 的证据/改写/复练结构。来源、固定版本及许可证见 [采用说明](./README.md) 和 `upstream/`。以下中文锚点、五环节划分、权重、缺证据处理与示例为销练多多适配设计，不是上述仓库原样规则，也不是原立项报告中已确认的企业五步法。

## 一、适用范围

- 默认用于通用 B2B 销售练习、完整聊天记录复盘、角色核对后的录音转写复盘。
- 单项训练在开始前指定考点。例如“解释产品原理”可以只评需求理解与价值说明，不能因为没有成交而扣分。
- 首次接触、续约、需求访谈使用不同场景配置；不要求一轮发言覆盖所有步骤，也不对每轮都重复评开场和收尾。
- 客户是否购买与销售表现分开。客户拒绝但销售解释准确、尊重意愿，也可能表现良好。
- 金融、医疗等行业的产品事实与专门约束必须另行配置。本稿不提供行业合规认证或法律结论。

## 二、五个环节与可观察评分锚点

每项 0/1/2 分：0 表示在完整可评的对话中未做到或明显违背；1 表示部分做到；2 表示关键动作完整且有证据。采用三档便于第一批人工标注，避免泛泛地猜测 76 分与 79 分的区别。

权重是首版试评配置，总计 100；尚未经过效果验证，不是来源仓库的权重。

| 考点 | 权重 | 0 分 | 1 分 | 2 分 |
|---|---:|---|---|---|
| S1 建立沟通与确认议程 | 10 | 忽略客户表达的时间限制，直接长篇推销；或没有说明本次来意 | 说明来意，但没有确认时间或客户当前关注点 | 简洁说明来意，确认方便程度，并与客户对齐此次交流重点 |
| S2 探索并核对需求 | 30 | 不理会客户提供的信息，直接推荐 | 问到现状或问题，但未核对影响、优先级，或未复述确认 | 根据回答继续追问，明确问题及影响/优先级，再由客户确认理解是否准确 |
| S3 将价值与需求对应 | 25 | 只堆功能，或与客户明确需求无关 | 收益与需求相关，但未说明作用、条件或未知边界，或未向客户确认 | 将价值解释对应客户需求，说明已知条件及未知边界，并由客户确认是否有帮助；无资料时明确待核实，不编造确定性效果 |
| S4 理解并回应异议 | 20 | 争辩、忽略顾虑，或未澄清就无依据承诺 | 认可顾虑并回应，但未弄清原因，或未确认回应是否解决问题 | 认可顾虑，澄清具体原因，给有依据的回应，询问顾虑是否得到解答 |
| S5 对齐下一步 | 15 | 强行催单，或只说“再联系”且没有可执行安排 | 提出具体动作，但缺少时间、责任人或客户确认 | 双方确认适当的动作、负责人和时间；明确拒绝时，确认结束并尊重不再联系的要求 |

说明：

- S2 中“影响/优先级”依任务选择，不强迫所有客户报预算、组织架构或量化损失。
- S3 不强迫编造 ROI；没有可核验的量化资料时，准确解释条件和未知边界比编数字更好。无产品资料不自动扣表达能力分；满足行为要求仍可得 2 分，产品事实与承诺授权单列为“未核实”。
- S4 只有场景设计要求并实际提供了异议机会才评。客户没有表达异议、也没有预设触发时不能算未做到。
- S5 的目标按场景预先配置：可能是发送资料、内部确认、预约演示或结束沟通，不默认要求成交。
- 表达清晰、倾听、尊重客户作为各环节的行为要求，不重复计分。文字记录不足以判断声音情绪、语速或真实发言时长。

## 三、常见异议如何训练

参考 LeadMagic 的六类划分，但每次都把原因当作待验证信息。

| 类型 | 客户可能说的话 | 要练习的动作 |
|---|---|---|
| 价格/价值 | 太贵了，预算不够 | 澄清预算限制、比较对象或收益疑问；有事实再解释，不自动给折扣 |
| 时机 | 现在不做，下季度再说 | 确认具体约束与合适的跟进时间；不虚构截止日期 |
| 竞品 | 我们已经在用别家 | 了解当前满意与不足，按可证实的差异回应，不贬低竞品 |
| 决策权限 | 我要问老板 | 确认决策流程、所需材料与各自下一步，不把对方当无效联系人 |
| 现状/变更成本 | 现在也够用，换起来麻烦 | 了解迁移、培训、流程等实际成本，判断是否值得改变 |
| 信任/风险 | 真能做到吗？会不会出问题？ | 说明验证方式、使用边界与已知风险；不知道的明确待确认 |

回应顺序可参考：认可顾虑 → 澄清原因 → 基于事实回应 → 确认是否解答。最后的确认步骤是本稿明确加入的评分要求。明确要求停止沟通时，停止推进，不把拒绝一律当成待突破的异议。

## 四、证据与评分状态

每个评估项保存：

| 字段 | 作用 |
|---|---|
| `rubric_id / rubric_version` | 规则名称与版本；历史报告不能随新规则被静默覆盖 |
| `criterion_id / weight` | 考点及本场固定权重 |
| `status` | `assessed`、`not_applicable`、`insufficient_evidence`、`evaluation_error` |
| `score` | 仅 assessed 可为 0/1/2，其余为 null |
| `evidence` | message_id、speaker、原话；若原始转写有可靠时间戳可另加时间，不由模型编造 |
| `checked_range` | 实际核查的消息范围，用于判断缺失行为；不把局部片段当整场 |
| `reason / missing_behavior` | 为什么是这个档位，还差哪个动作 |
| `next_practice` | 一个具体可重练动作或片段 |

判定边界：

1. 客户说了“迁移太麻烦”，不能凭这句话给销售的异议处理加分；必须看到销售的回应及必要的客户确认。
2. 客户亲口表达和销售自己的猜测分别标记；“销售说客户一定有需求”不等于客户确认。
3. 引用必须对应真实 message ID、说话人和原话。引用校验通过只能证明文字存在，不能代替语义判定。
4. 整场完整、机会明确，但销售没有做：可评 0 分，记录检查范围和相关前后文，不捏造一句“没做”的原话。
5. 录音丢段、聊天导入不完整、说话人不清楚：标记证据不足，不判 0 分，也不能默认及格。
6. 不适用项由场景配置或明确的机会条件决定，并留下原因。模型不能因为没找到证据就把必考项删除。
7. 模型调用或结构校验失败：标记评估失败，可重试；禁止默认 6 分或 60 分。

## 五、总分与达标

只有所有适用考点均为 assessed 时，才生成本场完整总分：

`总分 = round(100 × Σ(权重 × 单项分 / 2) / Σ适用权重)`

已确认不适用的项可从分母移除；必考项证据不足或评估失败时，总分保持 null，展示已完成单项及未完成原因。若没有适用项，同样不生成总分。

第一版不设置“80 分通过”等门槛。报告显示能力表现与待改进动作；合格线需在有人工标注的对照样本上校准。不同考点集合的总分不能直接比较，再练前后对比优先使用同一版本和相同考点。

## 六、独立记录的真实性与边界问题

下列是本产品拟采用的通用行为约束，不能冒充任何行业法规库：

- 有证据表明内容与批准资料矛盾：记录引用、资料来源及版本，进入人工核查。
- 未经授权的价格、交付或效果承诺：核查场景授权资料；没有资料时标记待核实，不自动认定销售撒谎。
- 虚构可核验客户案例、资格或确定性收益：保留原话及核对依据；不因总分高而隐藏。
- 客户明确拒绝继续或要求不再联系，仍持续施压：引用拒绝与后续行为，单列反馈。

每条记录使用“待核查 / 已确认 / 已排除”等状态，保留人工意见。规则未执行或资料缺失时，报告不能写“无违规”；应说明本次没有完成相应核对。正式认证及人事决定由业务方承担，不能由模型总分自动决定。

## 七、复盘展示示例（原创训练样例）

对话：

- c1 客户：“换系统太麻烦了，我们没精力折腾。”
- s1 销售：“我们功能很多，报表也很强。”
- c2 客户：“我不是说功能，是员工重新学很麻烦。”
- s2 销售：“明白，您更担心团队学习的成本，而不是功能数量，对吗？”
- c3 客户：“对，主要是这个。”

S4 异议处理：**1/2，部分做到**。

- 证据：s2 与 c3 表明销售澄清并核对了顾虑；s1 未回应最初的问题。
- 保留：后续确认了真正的顾虑是员工学习成本。
- 改进：尚未提供有依据的回应，也没有确认顾虑已得到解决。
- 下一句建议：“哪些岗位需要重新学习、目前最忙的时段是什么？我先确认这些，再核对我们能提供的培训安排。”
- 下一次练习：从“员工不愿重新学”这句开始，只练澄清变更成本与给出有依据的回应。

本例只评 S4，不据五句对话推断整场分数或成交概率，不编造产品已有培训服务。

## 八、接入与校准顺序

1. 先选择一个通用场景（如软件续约价格异议），配置事实、目标和适用考点。
2. 接入分项评估、证据校验和程序总分；保留当前模型失败重试机制。
3. 报告展示原话、判分理由及一个下一步动作；再次练习绑定该弱项。
4. 建立首批人工样本，覆盖优秀/一般/欠缺、拒绝、不完整记录、未授权承诺等情况。样本量及验收门槛由试点评审确定，不预先声称达到一致率。
5. 对比人工与 AI 的逐项判断、证据准确性、风险漏检和失败处理，修改锚点后固定版本，再考虑合格线。
